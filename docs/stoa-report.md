## Signal vs. noise

**Noise / intentional — not actionable:**

- **Non-determinism (77×)** — `new Date()` / `Date.now()` / `Math.random()`. Legitimate
  in a web app + backend (timestamps, cache-busting, UI). Only relevant where determinism /
  testability is explicitly required.
- **Wide public surface in schemas (10×)** — `schemas/src/*` is generated by vtseditor and
  must not be hand-edited. `Api/Species.ts` (39 exports) is a re-export wrapper; benign.
- **Most swallowed errors** — the majority are defensive `JSON.parse` fallbacks with an
  explanatory comment (`// not set / malformed — leave empty`) or `return null`. stoa flags
  syntactically (catch without log/rethrow) and does not count comments as handling.

**Real signal — worth fixing:**

### 1. Dependency cycles (4, high)

- `PageLoader.ts ↔ Sighting / Species / Profile / Tours / TourMap` — the thickest; the loader
  imports page classes while pages import the loader. Resolve via an interface / lazy import.
- `Map/BaseMap.ts ↔ Map/MapLayer.ts`
- `Pages/Roles/RoleRight/RoleRightEntry.ts ↔ RoleRightListWidget.ts`
- `Application/Backend.ts ↔ Routes/RouteLoader.ts`

### 3. Swallowed errors in services/providers

The subset that is *not* a parse fallback — `LiveAisService`, `OpenMeteoProvider`,
`ExternalTourService` swallow network/provider errors silently. Each deserves a log line,
otherwise outages are debugged blind.

## Proposed order

1. Resolve the 4 dependency cycles (small, high leverage).
2. Add logging to the service/provider swallowed-error catches (quick).
3. Decompose the top complexity offenders (`_aggregate` 160, `createExport` 104,
   `_paintIdwCanvas` 88) into helper functions.

Non-determinism and the generated-schema findings are intentionally left as-is.
